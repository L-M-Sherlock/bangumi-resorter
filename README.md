# Bangumi Resorter

一个静态优先、数据本地保存的 Bangumi 收藏重排工具。它读取你已经打过分的条目，通过两两比较、带正则化先验的 Bradley–Terry 模型和 Laplace 后验近似，逐步得到可检查的个人偏好顺序；默认只读，只有在结果页 Danger Zone 明确确认后才会写回评分。

## 功能

- 读取 Bangumi 全部 `rate > 0` 的收藏，并按动画、书籍、音乐、游戏和三次元分别排序
- 可选个人令牌用于读取私有收藏；写回评分时必须重新提供具有 `write:collection` 权限的令牌。令牌只存在当前页面内存，不进入 IndexedDB、日志或导出文件
- 按下一题的后验期望信息增益选择配对，并定期执行覆盖探索与校准复问
- 已开始的会话可在快速、标准、精细模式间原地切换；保留全部判断并立即重算后验、下一题与剩余预测
- 可解释的总体相邻容差停止标准：至少 90% 的作品最多偏移一档，该事件的后验概率下界达到 90%
- Worker 内运行带 L2 先验的 Bradley–Terry / MAP 拟合与确定性 Laplace 后验抽样；停止边界含糊时自动提高抽样精度
- 用后验收缩 Monte Carlo 给出剩余判断数区间与下一检查点
- 支持 3–20 档输出评分；均匀、保持原分布、高分辨率尾部、反 J、自定义权重五种分布会按当前档数重采样，新会话默认 10 档高分辨率尾部
- 新会话默认从零开始，也可从一个同账号、同媒介的既有会话一次性导入仍适用的判断；支持跨收藏快照
- 可搜索并多选个人收藏标签来限定比较范围；多个标签按“全部匹配”取交集，未选择标签时包含当前媒介与收藏状态下的全部作品
- 重新同步后可把旧会话升级到最新收藏：保留旧会话，一次性导入共有作品的有效判断，并重新纳入新增作品
- 已有会话可以按不同标签范围派生为新会话，原会话不变，范围内仍有效的判断会被复制并重新建模
- 可在结果页按标题、原名、排名或 Bangumi ID 搜索任意两个会话内条目并添加比较，也可永久删除本会话中的单条判断并即时重算
- 可在收藏概览删除整个排序会话及其判断与模型；收藏快照不会被连带删除
- 可在结果页 Danger Zone 预览并写回 10 档新评分；线上评分与会话快照冲突或已经移出收藏的条目会被跳过，写后重新读取验证
- IndexedDB 自动保存；CSV 结果导出和完整 ExportV1 JSON 备份/迁移
- 带演示数据，可在不连接 Bangumi 的情况下体验完整流程
- 公开的原理长文解释评分聚集、模型、主动选题、分桶、停止与限制；应用内技术术语提供键盘和移动端可用的解释浮窗

方法受到 [Gwern 的 Resorter](https://gwern.net/resorter) 启发。这里采用稳定的正则化 Bradley–Terry 优化，按模式选择强评分先验、中等评分先验或无评分顺序先验，并用快速 Laplace 近似估计“当前分桶在模型内是否稳定”。

## 本地开发

要求 Node.js 22.13 或更高版本。开发脚本可直接在 macOS、Linux，以及 Windows PowerShell 或命令提示符中运行，不需要 WSL。

```shell
npm ci
npm run dev
```

打开 `http://localhost:3000`。常用检查：

```shell
npm run typecheck
npm run test:unit
npm run lint
npm run build
npm run test:e2e
```

生产静态文件位于 `dist/client`。

### Windows

建议使用 Node.js 官方安装包或 nvm-windows 安装当前 LTS 版本。在 PowerShell 中，从仓库目录直接运行：

```powershell
npm ci
npm run dev
```

若 PowerShell 因本机执行策略阻止 `npm.ps1`，可以改用同目录下的 `npm.cmd`，无需修改项目或全局执行策略：

```powershell
npm.cmd ci
npm.cmd run dev
```

## 部署

这个项目没有服务端数据库和密钥，适合 GitHub Pages、Cloudflare Pages 等静态托管。运行时只会从浏览器直接请求 `https://api.bgm.tv/v0`；用户数据留在对应域名的 IndexedDB 中。因此更换域名不会自动带走本地数据，需要先下载 JSON，再到新站点导入。

### GitHub Pages

仓库已包含 `.github/workflows/deploy-pages.yml`。在仓库 Settings → Pages 中把 Source 设为 GitHub Actions，推送 `main` 即会测试、按仓库子路径构建并部署。工作流也支持 `username.github.io` 这类根站点仓库。

### 其他子路径托管

如果站点部署在 `/some-path` 下，构建时设置环境变量。

macOS / Linux：

```bash
NEXT_PUBLIC_BASE_PATH=/some-path \
NEXT_PUBLIC_SITE_URL=https://example.com \
npm run build
```

Windows PowerShell：

```powershell
$env:NEXT_PUBLIC_BASE_PATH = "/some-path"
$env:NEXT_PUBLIC_SITE_URL = "https://example.com"
npm run build
```

Windows 命令提示符：

```bat
set "NEXT_PUBLIC_BASE_PATH=/some-path"
set "NEXT_PUBLIC_SITE_URL=https://example.com"
npm run build
```

## 数据与隐私

- 同步、排序和预览之外的日常操作不会写入 Bangumi；只有 Danger Zone 最终确认会逐条发送评分 `PATCH`。
- 个人令牌不会持久化，也不会进入备份；写回结束、关闭 Danger Zone 或刷新页面后即消失。
- 私有条目的名称、评分和判断会进入本地 IndexedDB 与 JSON 备份；界面会在导出前提示。
- 浏览器清理站点数据会删除 IndexedDB。建议每完成约 20 次判断后下载 JSON 备份。
- 导入永远创建新项目，不覆盖已有数据；单个备份文件限制为 20 MB。

## 模型简述

每个条目有一个潜在偏好强度。比较结果的似然由两者强度差的 logistic 函数给出；平局按半胜处理。优化器使用 L2 正则，Newton 外循环配合预条件共轭梯度求解，并用线搜索保证目标函数不下降。快速模式强依赖原评分，只比较很近的候选并每 25 题探索全局；标准模式使用中等评分先验和每 10 题一次的均衡探索；精细模式不采用原评分顺序，以零均值弱正则、宽边界候选和每 5 题一次的全局探索让比较本身支撑排序。当前会话可以随时切换模式；切换只更新模式和模型版本，已有判断、作品范围与评分分布不变，完整后验及下一题会按新参数重新计算。

在 MAP 解处，应用程序把负对数后验的 Hessian 当作高斯精度矩阵，用 PCG 生成 Laplace 后验样本。基础样本数随本会话证据从 64 升至 128；如果 90% Monte Carlo 区间跨过停止门槛，则用 2048 个样本重新判断。抽样随机流只由会话种子决定，不再混入模型版本；拟合也从当前模式的先验规范化重算，因此相同作品、判断、分布和模式必然返回相同诊断，切换到其他模式再切回不会改变剩余题量。下一对的普通候选来自当前邻居和分桶边界，按回答与整个潜在偏好状态之间的期望互信息排序，并惩罚重复配对；每第 10 个非校准问题优先覆盖比较次数少且尚未稳定的条目，避免贪心策略反复追问同一小组；每第 20 个问题尝试换边复问较早的配对。

停止标准把损失定义为实质性的跨档错误：在一次后验样本里，至少 `ceil(0.9 × N)` 个条目相对当前 K 档分桶不得偏移超过一档，等价于最多 `N - ceil(0.9 × N)` 个条目可以跨两档。K 可在 3–20 之间选择；两档没有开放，因为“两档内最多偏移一档”会恒成立。应用程序用满足该总体事件的样本比例估计后验概率，并要求其 90% Wilson Monte Carlo 下界达到 90%，同时满足最低本会话证据量。模式要求按先验鲁棒性嵌套：快速只需强评分先验模型通过；标准要求快速与中等先验模型同时通过；精细要求强、中、零评分顺序先验三个模型全部通过。因此更高模式不可能在较低模式尚未通过时先行达标。界面同步展示当前模式的跨两档作品数与最大偏移，并在停止详情中列出每一级模型的 MC 下界和当前瓶颈；校准复问以 Beta(1,1) 后验描述判断波动，仅作诊断，不阻止停止，也不进入剩余题量预测。

应用程序没有预先承诺的“完成题数”，也不设置答题次数上限。每次回答后，它为当前模式要求的各级 Laplace 后验运行同一组 64 条信息收缩路径，在单次比较粒度上二分定位每条路径中最晚通过的模型，再给出 10%/50%/90% 分位数。更高模式包含更多模型且使用更保守的预测效率，因此动态剩余次数保持快速 ≤ 标准 ≤ 精细。模拟会使用有限的内部前瞻窗口以控制计算量，但该窗口不会阻止继续比较；`0/64` 只表示本轮窗口内没有观察到成功路径，不是不可达证明。

最终的连续潜在强度用于推断顺序，但其绝对数值、距离和标准差不直接构成停止条件；停止条件只读取每个后验样本映射出的 K 档结果。原评分始终保留为 1–10 分先验，输出评分则由当前 K 和分布配置重新映射。切换 K 或分布不丢失已有判断，但会重新计算分桶稳定度、剩余预测和下一对，因为不同设置关心的边界不同。

每次同步都会保存独立的收藏快照，已有会话不会被静默改写。新建会话默认不导入历史；如果明确选择一个来源会话，系统只在创建时复制目标范围中仍有效的判断，跳过记录、范围外记录和孤立校准不会导入。副本记录直接来源和最初的根判断，按根判断幂等，来源随后新增、删除或被整体删除都不会改变目标会话。用户也可以把旧会话派生到最新快照：升级前显示新增、移除、原评分变化和可导入判断数；升级与标签派生使用相同的一次性导入规则。新作品从最新原评分先验开始，随后由覆盖探索和信息增益选题接入排序。新会话会重新计算完整后验、分桶与停止预测，旧会话仍可独立打开或删除。

标签范围使用收藏条目自带的个人标签，不使用 Bangumi 公共条目标签。筛选规则作为会话的一部分保存：多个标签必须同时命中；升级到新快照时会在最新收藏上重新执行该规则，因此新增且匹配的作品会自动进入，失去标签或不再匹配的作品会退出。调整已有会话的标签范围不会原地改写历史，而是在原快照上派生新会话，并在创建前预览作品增减及可导入判断数。

这里展示的概率与剩余区间都是 Bradley–Terry、Laplace 近似及后验收缩预测内部的结果，不是作品客观质量、用户永远不改变意见的概率，也不是承诺题量。校准复问单独反映判断波动，不改变停止结论或似然温度。
