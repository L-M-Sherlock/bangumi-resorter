# Bangumi Resorter

一个静态优先、数据本地保存的 Bangumi 收藏重排工具。它读取你已经打过分的条目，通过两两比较、带正则化先验的 Davidson 三结果模型和 Laplace 后验近似，逐步得到可检查的个人偏好顺序；默认只读，只有在结果页 Danger Zone 明确确认后才会写回评分。

## 功能

- 读取 Bangumi 全部 `rate > 0` 的收藏，并按动画、书籍、音乐、游戏和三次元分别排序
- 可选个人令牌用于读取私有收藏；写回评分时必须重新提供具有 `write:collection` 权限的令牌。令牌只存在当前页面内存，不进入 IndexedDB、日志或导出文件
- 按下一题的后验期望信息增益选择配对，并按来源年龄与同对相关性修正后的有效权重定期执行覆盖探索及校准复问
- 先验强度与停止严格度独立：强/弱先验决定旧评分的作用，快速/标准/精细分别要求 80%/90%/95% 的作品最多偏移一档，三个覆盖事件统一要求 90% MC 下界达到 90%，并检查有效权重、唯一作品对与作品覆盖
- 已开始的会话可原地切换两个维度并保留全部判断；切换先验会完整重算，切换停止严格度直接复用同一后验与三档预测
- Worker 内运行带 L2 先验的加权 Davidson / MAP 拟合与确定性 Laplace 后验抽样；停止边界含糊时自动提高抽样精度
- 用逐题后验模拟 Monte Carlo 给出剩余判断数区间与下一检查点
- 支持 3–20 档输出评分；均匀、保持原分布、高分辨率尾部、反 J、自定义权重五种分布会按当前档数重采样，新会话默认 10 档高分辨率尾部
- 新会话默认从零开始，也可从一个同账号、同媒介的既有会话一次性导入仍适用的判断；已有会话也可在结果页预览并追加导入，支持跨收藏快照且按根判断去重，同对历史按相关性与来源年龄折权
- 可搜索并多选个人收藏标签来限定比较范围；多个标签按“全部匹配”取交集，未选择标签时包含当前媒介与收藏状态下的全部作品
- 重新同步后可把旧会话升级到最新收藏：保留旧会话，一次性导入共有作品的有效判断，并重新纳入新增作品
- 已有会话可以按不同标签范围派生为新会话，原会话不变，范围内仍有效的判断会被复制并重新建模
- 可在结果页按标题、原名、排名或 Bangumi ID 搜索任意两个会话内条目并添加比较，也可永久删除本会话中的单条判断并即时重算
- 可在收藏概览删除整个排序会话及其判断与模型；收藏快照不会被连带删除
- 可在项目切换器预览并删除当前收藏快照及其关联会话、判断、导入批次和模型；普通账号至少保留一个快照，删除当前快照后自动切换到同账号最近的剩余快照
- 可在结果页 Danger Zone 预览并写回 10 档新评分；线上评分与会话快照冲突或已经移出收藏的条目会被跳过，写后重新读取验证
- IndexedDB 自动保存；CSV 结果导出和完整 ExportV1 JSON 备份/迁移，支持同账号覆盖恢复、按会话选择性合并以及多账号/收藏快照切换
- 带演示数据，可在不连接 Bangumi 的情况下体验完整流程
- 公开的原理长文解释评分聚集、模型、主动选题、分桶、停止与限制；应用内技术术语提供键盘和移动端可用的解释浮窗

方法受到 [Gwern 的 Resorter](https://gwern.net/resorter) 启发。这里采用稳定的正则化 Davidson 优化，可独立选择强原评分先验或弱零均值先验，并用快速 Laplace 近似估计“当前分桶在模型内是否稳定”。

## 本地开发

要求 Node.js 22.13 或更高版本。开发脚本可直接在 macOS、Linux，以及 Windows PowerShell 或命令提示符中运行，不需要 WSL。

```shell
npm ci
npm run dev
```

打开 `http://localhost:3000`。常用检查：

```shell
npm run typecheck
npm run test:unit
npm run lint
npm run build
npm run test:e2e
```

比较性能基准使用一组确定性的匿名合成数据，默认模拟 284 部作品、已有 1,212 条判断（含 491 条导入和 59 次校准复问），再加入一次新回答。核心基准逐项测量相关性/时间衰减折算、模型拟合、后验诊断、停止预测和下一题选择；浏览器基准使用真实 Chromium Worker 拓扑，分别测量排名与下一题可见的快速阶段，以及不阻塞继续作答的后台 64 路径预测阶段（手机生产配置使用 32 路径）。它不会读取或修改本地用户数据，也不把设备相关的 IndexedDB 持久化耗时混入模型耗时。

```shell
npm run benchmark:comparison
```

也可以分别运行 `benchmark:comparison:core` 和 `benchmark:comparison:browser`。浏览器基准默认先预热一次再测量三次；可用 `COMPARISON_BENCH_ITERATIONS` 调整稳态样本数。

生产静态文件位于 `dist/client`。

### Windows

建议使用 Node.js 官方安装包或 nvm-windows 安装当前 LTS 版本。在 PowerShell 中，从仓库目录直接运行：

```powershell
npm ci
npm run dev
```

若 PowerShell 因本机执行策略阻止 `npm.ps1`，可以改用同目录下的 `npm.cmd`，无需修改项目或全局执行策略：

```powershell
npm.cmd ci
npm.cmd run dev
```

## 部署

这个项目没有服务端数据库和密钥，适合 GitHub Pages、Cloudflare Pages 等静态托管。运行时只会从浏览器直接请求 `https://api.bgm.tv/v0`；用户数据留在对应域名的 IndexedDB 中。因此更换域名不会自动带走本地数据，需要先下载 JSON，再到新站点导入。

### GitHub Pages

仓库已包含 `.github/workflows/deploy-pages.yml`。在仓库 Settings → Pages 中把 Source 设为 GitHub Actions，推送 `main` 即会测试、按仓库子路径构建并部署。工作流也支持 `username.github.io` 这类根站点仓库。

### 其他子路径托管

如果站点部署在 `/some-path` 下，构建时设置环境变量。

macOS / Linux：

```bash
NEXT_PUBLIC_BASE_PATH=/some-path \
NEXT_PUBLIC_SITE_URL=https://example.com \
npm run build
```

Windows PowerShell：

```powershell
$env:NEXT_PUBLIC_BASE_PATH = "/some-path"
$env:NEXT_PUBLIC_SITE_URL = "https://example.com"
npm run build
```

Windows 命令提示符：

```bat
set "NEXT_PUBLIC_BASE_PATH=/some-path"
set "NEXT_PUBLIC_SITE_URL=https://example.com"
npm run build
```

## 数据与隐私

- 同步、排序和预览之外的日常操作不会写入 Bangumi；只有 Danger Zone 最终确认会逐条发送评分 `PATCH`。
- 个人令牌不会持久化，也不会进入备份；写回结束、关闭 Danger Zone 或刷新页面后即消失。
- 私有条目的名称、评分和判断会进入本地 IndexedDB 与 JSON 备份；界面会在导出前提示。
- 浏览器清理站点数据会删除 IndexedDB。建议每完成约 20 次判断后下载 JSON 备份。
- JSON 导入会先严格校验结构和引用：目标账号不存在时创建新项目，已存在时默认按会话选择性合并，也可输入账号名执行该账号范围内的覆盖恢复；其他账号始终保留。单个备份文件限制为 20 MB。
- 项目切换器可预览并删除当前收藏快照及其关联会话、判断、批次和模型；需要输入账号名确认，其他快照与账号不会改变，清理操作会留在本地审计中。普通账号的最后一个快照不能删除，需先同步或导入另一个快照。
- 升级时识别出的旧版导入副本会在项目切换器中额外标记，并沿用专门的旧副本清理提示。

## 模型简述

每个条目有一个潜在偏好强度。左胜、右胜和平局统一使用 Davidson 三结果似然；共享的平局强度带弱正则并随当前判断一起做 MAP 估计，不再把平局拆成半胜，也没有只在预测中启用的固定 lapse。拟合、期望信息增益和未来回答模拟都读取同一组 Davidson 概率。优化器使用 L2 正则，Newton 外循环配合预条件共轭梯度求解，并用线搜索保证目标函数不下降；若达到迭代上限、线搜索失败或出现非有限值，界面会显示诊断，并关闭 `ready` 与有限剩余题量。先验强度是独立维度：强先验使用 `priorStrength=1.2, priorScale=0.7`，让原评分建立明显的初始顺序；默认弱先验使用 `priorStrength=0.05, priorScale=0`，只保留很弱的零均值正则。弱先验下能力相同时仅按作品 ID 做确定性 tie-break，不读取原评分。两者共用宽边界候选、每 5 个非校准问题一次的全局探索和半径 12。切换先验会保留判断、作品范围与评分分布，并按新先验完整重算后验、下一题与剩余预测。

在 MAP 解处，应用程序把负对数后验的 Hessian 当作高斯精度矩阵，用 PCG 生成 Laplace 后验样本。基础样本数随本会话原始回答从 64 升至 128；如果 90% Monte Carlo 区间跨过任一停止门槛，则用 2048 个样本重新判断。每批样本会精确重心化到 MAP，只移动有限样本均值而保留协方差。抽样随机流只由会话种子决定，不再混入模型版本；拟合也从当前先验规范化重算，因此相同作品、判断、分布和先验必然返回相同诊断，切换到另一先验再切回不会改变剩余题量。下一对的普通候选来自当前邻居和分桶边界，按三结果回答与整个潜在偏好状态之间的期望互信息排序，并以同对相关性修正后的有效权重惩罚重复配对；每第 5 个非校准问题优先覆盖来源年龄与同对相关性修正后有效权重较少、且尚未稳定的条目，避免陈旧重复导入或校准复问的原始次数制造虚假覆盖；每第 20 个问题尝试换边复问较早的配对。

停止标准把损失定义为实质性的跨档错误：在一次后验样本里，快速、标准、精细分别要求至少 `ceil(0.80 × N)`、`ceil(0.90 × N)`、`ceil(0.95 × N)` 个条目相对当前 K 档分桶不得偏移超过一档，等价于最多允许其余条目跨两档。K 可在 3–20 之间选择；两档没有开放，因为“两档内最多偏移一档”会恒成立。应用程序分别估计三个嵌套覆盖事件的后验概率；每个事件的 90% Wilson Monte Carlo 下界都必须达到 90%。此外还必须同时达到相关性修正后的最低有效权重、最低唯一作品对数，并让当前档位要求的 80%/90%/95% 作品各自获得至少 0.5 的关联有效权重。三档不改变先验、后验或选题，因此 ready 状态严格嵌套，切换停止档位只需选择已经缓存的检查和预测。界面同步展示跨两档作品数、最大偏移、当前 MC 下界和三项证据门槛。

应用程序没有预先承诺的“完成题数”，也不设置答题次数上限。每次回答先在排序 Worker 中生成权威后验、三档停止诊断和下一题并立即恢复作答；动态剩余预测随后在独立、可取消的后台 Worker 中更新，同一会话出现新模型时会终止旧预测，陈旧版本不能写回。后台预测从当前 Laplace 后验抽取代表性联合粒子：桌面端最多 64 条，手机端最多 32 条；每条路径都按实际策略重新选择普通题、覆盖探索或到期的校准复问，并使用该路径真值粒子自身的 Davidson 平局强度模拟回答。会话分析历史检查点固定使用 64 条路径，以保证跨设备缓存可比。信念更新同时传播能力与 `log ν`：若未来题是重复作品对，会先撤出该作品对旧的相关簇似然，再用新增答案后的总质量重新计算整簇折权似然，经二维局部 Laplace 矩匹配和协方差传播更新粒子，而不是只给新答案追加一个边际权重。

路径中的局部后验只负责每 16 个模拟答案一次的低成本筛查，不能授权停止。局部 MC 下界触及 90% 门槛、距离上次完整刷新达到 128 个答案，或预测窗口结束时，系统才用该路径的完整历史暖启动 MAP、重建 Laplace 后验，再由刷新后的全局后验确认三档停止事件。这样保留完整后验确认的停止正确性，同时避免每个检查点完整拟合。每条路径同时记录 80%、90%、95% 覆盖事件及三项证据门槛首次达标的时刻，最后分别报告 10%/50%/90% 分位数；三档共用每一条路径，所以快速 ≤ 标准 ≤ 精细。大型收藏的内部前瞻窗口当前最多约 500 次；它不限制继续比较，`0/64` 也只表示窗口内没有观察到成功路径。该范围是当前模型下的条件情景分位数，不是校准过的预测区间或题量承诺。

会话分析的解释性指标按判断实际发生时间重建，导入判断使用 `sourceCreatedAt`，因此固定步长检查点可以落在一个导入批次的来源历史内部；动态剩余与回溯另按 `createdAt` 重建证据何时真正对当前会话可见，不能把后来导入的判断当成当时选题器已知的信息。停止只在离散检查点被观察，误差和区间命中因此使用相邻检查点之间的停止窗口，而不是把后一个检查点当成精确停止题数。预测之后若发生导入或手动判断并改变未来可用证据，该点按策略干预截断。至少 3 个闭合区间中若 80% 同方向错过停止窗口，且 P50 中位偏差达到一个检查点步长，分析页会警告并隐藏该档历史 P10–P90 阴影；P50 仍作为模型内情景显示。相邻回溯点共享历史且高度相关，系统不会从单一会话拟合经验乘数。

最终的连续潜在强度用于推断顺序，但其绝对数值、距离和标准差不直接构成停止条件；停止条件只读取每个后验样本映射出的 K 档结果。原评分数据始终保留，强先验会用它建立顺序，弱先验不会；输出评分则由当前 K 和分布配置重新映射。切换 K 或分布不丢失已有判断，但会重新计算分桶稳定度、剩余预测和下一对，因为不同设置关心的边界不同。

每次同步都会保存独立的收藏快照，已有会话不会被静默改写。新建会话默认不导入历史；如果明确选择一个来源会话，系统只在创建时复制目标范围中仍有效的判断。已有会话可在结果页的“判断管理”中选择同账号、同媒介的其他会话，先预览可导入、已存在、范围外、跳过和无效校准数量，再把新增判断原子写入并立即重算模型。跳过记录、范围外记录和孤立校准不会导入。副本记录直接来源、来源时间和最初的根判断，按根判断幂等，来源随后新增、删除或被整体删除都不会改变目标会话。所有非跳过判断都会入模，包括手动判断、导入判断和校准复问；同一无序作品对的原始权重总量按工作相关系数 `ρ=0.5` 折算为 `m/[1+max(0,m-1)ρ]`，整数 `m≥1` 时就是常见的 `m/[1+(m-1)ρ]`，因此十次同对判断不会伪装成十个独立样本。导入时已经过去的来源年龄先按 365 天半衰期折减；这里的 `m` 是折减后的分数权重，低于一条完整判断时不会被相关性公式反向放大。用户也可以把旧会话派生到最新快照：升级前显示新增、移除、原评分变化和可导入判断数；升级与标签派生使用相同的一次性导入规则。新作品按会话所选的强或弱先验进入模型，随后由覆盖探索和信息增益选题接入排序。新会话会重新计算完整后验、分桶与停止预测，旧会话仍可独立打开或删除。

标签范围使用收藏条目自带的个人标签，不使用 Bangumi 公共条目标签。筛选规则作为会话的一部分保存：多个标签必须同时命中；升级到新快照时会在最新收藏上重新执行该规则，因此新增且匹配的作品会自动进入，失去标签或不再匹配的作品会退出。调整已有会话的标签范围不会原地改写历史，而是在原快照上派生新会话，并在创建前预览作品增减及可导入判断数。

这里展示的概率与剩余范围都是加权 Davidson、Laplace 近似及逐题后验情景模拟内部的结果，不是作品客观质量、用户永远不改变意见的概率，也不是承诺题量。校准复问的一致率单独反映判断波动；复问答案本身会像其他同对重复判断一样相关折权后参与拟合、证据门槛和未来路径。
